# skill-trace File Format Spec

Plain text is canonical. Since v1.4.0 the unit of storage is **one markdown file
per lesson** (schema 2) with a typed frontmatter header, kept in a *store*
directory. The single-file logs that earlier versions wrote (schema 1) are still
read on first contact and migrated; afterwards they exist only as **generated
rollups**. The viewer's in-memory index is derived and disposable.

## Stores

| Store | Path | Who writes it | Travels with |
|-------|------|---------------|--------------|
| **Project** | `<project>/.claude/skill-trace/` | `log-lesson`, the sync hook, `/skill-trace` | the repo (commit it like shared agents/skills) |
| **Global** | `~/.claude/skill-trace/` | the sync hook, **only from trusted projects** | you |

Each store contains:

```text
lessons/<date>-<slug>--<id8>.md   # one file per lesson (schema 2)
index.md                          # generated: OKF index grouped by Stack tag
tombstones.txt                    # ids deleted here; a re-sync cannot resurrect them
```

The store path is defined in exactly one place (`storePaths()` in `viewer/store.js`).

## Lesson file (schema 2)

```markdown
---
id: 01J9Q3KXW7M2A8R5V6T0ZB4HNE
type: Lesson
schema: 2
title: Strip the UTF-8 BOM before parsing
date: 2026-06-10
stack: [encoding, parsing, node]
projects: [sync-service]
seen: 1
generated_by: claude-code
created: 2026-06-10T14:02:11Z
updated: 2026-06-10T14:02:11Z
hash: 7f3a9c1e4b2d
---
**Problem:** A file saved with a BOM prefixed the first header, so the parser
matched zero records.

**Solution:** Strip a leading BOM on read; reading as plain UTF-8 does not
remove it.

**Takeaway:** Always strip a leading BOM before line-anchored parsing.
```

Filename: `<date>-<slug>--<id8>.md`. The date and slug are for humans browsing the
folder; the id suffix (the last 8 characters of the id, its random part) keeps the
name unique and stable across retitles — retitling renames the file, the id does
not change.

### Frontmatter fields

| Field | Written by | Rule |
|-------|-----------|------|
| `id` | tool | ULID: 26 chars, time-sortable, unique. Never hand-set. Same id in the project store and its global mirror. |
| `type` | tool | `Lesson`. Reserved for future types. |
| `schema` | tool | `2`. |
| `title` | author | One line. States the lesson, not the task. |
| `date` | tool | `YYYY-MM-DD`, from the session environment. |
| `stack` | author | Lowercase tags from the controlled vocabulary below. May be empty. |
| `projects` | tool | Provenance slugs. Project store: that project. Global store: the union of every project that contributed it. |
| `seen` | tool | Starts at 1. Incremented when the same lesson recurs (see dedup) instead of writing a duplicate. |
| `generated_by` | tool | `claude-code` (the `log-lesson` skill), `migration` (from a schema-1 file), `hook` (a hand-written entry absorbed from a rollup). Optional. |
| `created` / `updated` | tool | UTC, second precision, unquoted. `updated` is the content's time, not the sync time. |
| `hash` | tool | `sha1(normalized body)[:12]`. Recomputed on load; a mismatch marks the lesson **edited outside the tool** (informational). The next sync re-blesses it. |

The frontmatter is a deliberately small YAML subset: scalars, `[a, b]` lists,
quoted strings. No YAML library is involved.

### Body

The same three sections as always, each optional: `**Problem:**`, `**Solution:**`,
`**Takeaway:**`. The `**Stack:**` line of schema 1 is now the `stack` field.

## Identity and dedup

A lesson's identity is its **id**. Within a store, an incoming lesson is matched in
this order:

1. **same id** — the same lesson re-synced (project → global). The project copy is
   the author: any content difference is taken, `seen` is not bumped.
2. **same body hash** — the same lesson from another project: provenance merges,
   `seen` += 1.
3. **same title within 7 days** — a reworded recurrence: provenance merges,
   `seen` += 1.

Body normalization for the hash: lines trimmed, blank lines dropped, legacy
`**Project:**` lines ignored. Whitespace-only edits do not change identity.

A **tombstoned** id (deleted in that store) is never written again by a sync.
Deleting globally never touches a project store, and vice versa.

## Generated rollups (schema 1, output only)

For grep and for anything that still reads the old shape, the tool regenerates a
single schema-1 file **from** the store and never reads it back as source:

- `~/.claude/global-skills.md` — always.
- `<project>/docs/skills.md` — **only if the project already had one.** A new
  project gets no `docs/` folder; its readable summary is the store's `index.md`.

A rollup starts with a marker that identifies it as generated:

```markdown
<!-- generated by skill-trace from .claude/skill-trace/lessons — edit the lesson files, not this -->
<!-- skill-trace-schema: 1 -->
```

Entries typed **into** a rollup by hand are not lost: the next sync absorbs any
entry whose body hash the store does not have, then regenerates the file.

## Legacy single file (schema 1, input)

```markdown
## [YYYY-MM-DD] — Short title <!-- project-slug -->

**Stack:** node, concurrency, locking

**Problem:** …

**Solution:** …

**Takeaway:** …
```

Bare `## YYYY-MM-DD` headers are accepted. The header's trailing comment is
provenance. A leading UTF-8 BOM is stripped.

**Migration rule.** The first time the tool meets a hand-written schema-1 file
with no store beside it, it splits the file into lesson files (new ids,
`generated_by: migration`, `created` = the entry date), deduplicates by body hash
merging provenance, **renames** the original to `*.legacy-<YYYYMMDD>.md` (user
data is never deleted), and writes a generated rollup in its place. Re-running is
a no-op.

## Stack tags (controlled vocabulary)

`stack` names the technologies and concepts a lesson is about. It is the
**relevance key** context injection (v1.5.0) will score against, so the vocabulary
is controlled: it grows by deliberate addition, never by typo.

**Authoring is gated by the `log-lesson` skill.** The skill reads this list before
writing; an unrecognized tag is confirmed with the user and, on approval, added
here in the same change, so vocabulary growth is an auditable diff.

Current vocabulary:

```text
node, powershell, bash, python, sqlite, sql-server, css, html, http, git,
claude-code, concurrency, locking, security, encoding, regex, testing,
ci, hooks, parsing, performance, filesystem, api, markdown
```

## Schema versions

| Schema | Shape | Status |
|--------|-------|--------|
| 1 | single markdown file, `## [date] — Title <!-- prov -->` blocks, file-level `<!-- skill-trace-schema: 1 -->` marker | **input** (migrated on first contact) and **output** (generated rollups) |
| 2 | one file per lesson with frontmatter, `schema: 2` per file | **canonical** since v1.4.0 |

Parsers treat a missing schema-1 marker as schema 1 and a newer-than-known
version as best-effort, never as a crash. The per-entry version override once
reserved for schema 2 inside the provenance comment is superseded by the
`schema` frontmatter field and is not used.
